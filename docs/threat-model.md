# lab01 威胁模型

## 一、安全目标

本项目要解决 OAuth 授权后的数据过度访问问题：

> 第三方应用即使持有合法的 OAuth access token，也不能以明文读取用户当前批准任务之外的数据字段。

项目关注的是“应用已经合法获得 token 之后还能读取多少数据”，而不是重新实现 OAuth 授权协议。

## 二、保护资产

- 日历事件的开始时间 start。
- 日历事件的结束时间 end。
- 事件标题 title。
- 地点 location。
- 参会人 attendees。
- 描述 description。
- 字段加密密钥。
- 用户任务授权记录。
- OAuth 授权码、access token 和 refresh token。

## 三、主要攻击者

主要攻击者是好奇、被攻陷或存在越权行为特征的第三方 OAuth 应用。该攻击者具备以下能力：

- 已经取得当前用户合法的 read:calendar access token。
- 可以调用日历资源和任务密钥接口。
- 可以修改 task_id、resource_id 或请求中的其他参数。
- 可以保存、重放观察到的响应和密文。
- 可以尝试跨任务、跨用户、跨客户端使用已经获得的信息。

攻击者不能：

- 攻破 OAuth 授权服务器、资源服务器或数据库。
- 直接破解 AES-256-GCM。
- 在没有对应字段密钥时解密字段。
- 任意读取用户设备中的应用进程内存。

## 四、信任边界

以下组件在当前威胁模型中可信：

- OAuth 授权服务器。
- redirect URI、PKCE、scope 和 token 校验逻辑。
- 资源服务器和字段加密组件。
- 任务目录与任务密钥服务。
- 数据库和本地实验配置。

以下实体不可信：

- 第三方 OAuth 应用。
- 请求里的 task_id 和 resource_id。
- 应用提交的“本任务需要哪些字段”声明。

当前原型假设浏览器和 API 之间的 TLS 正常。lab 环境使用 Caddy 本地证书，因此只适合可信本机测试。

## 五、安全性质

| 编号 | 安全性质 | 当前状态 |
|---|---|---|
| G1 | calendar.freebusy 只允许解密 start 和 end | 已实现 |
| G2 | 未单独批准更宽任务时，修改 task_id 不能取得更多密钥 | 已实现 |
| G3 | 不能使用其他用户的资源 ID 获取密钥 | 已实现 |
| G4 | 密文必须绑定用户、资源、字段和策略版本 | 已实现 |
| G5 | 撤销 consent 时同步撤销任务 grant 和 token | 已实现 |

| G7 | 已释放密钥会过期，撤销后未来数据不能继续解密 | 未完成，计划使用 key epoch 和轮换 |
| G8 | 密钥释放和拒绝决策有结构化审计日志 | 未完成 |

## 六、威胁与控制对应表

| 编号 | 威胁 | 攻击方式 | 当前控制 | 验证方式 |
|---|---|---|---|---|
| T1 | 字段过度读取 | 在 freebusy 任务中读取标题或描述 | 字段加密，只释放 start 和 end 密钥 | lab01/reproduce.py |
| T2 | 任务混淆 | 把 task_id 改为用户没有批准的任务 | 必须存在对应的 active task grant | Go 单元测试 |
| T3 | 跨用户资源 | 请求其他用户的 calendar resource ID | 密钥接口绑定 token subject | 控制器校验 |
| T4 | 密文替换 | 把一个字段或用户的密文换到另一个字段 | AAD 绑定 user、resource、attribute、version | 加密单元测试 |
| T5 | 只有 OAuth 权限 | 合法 token 请求全部明文 | 固定版本只返回密文，不释放多余字段密钥 | 客户端流程 |
| T6 | 撤销后继续访问 | consent 撤销后继续申请字段密钥 | 同时撤销 task grant 和 token | consent 流程 |
| T7 | Token 被窃取 | 攻击者拿到 bearer token 后申请密钥 | 尚未完成，计划增加客户端 PoP | 待实现 |

## 七、明确不负责的风险

- redirect URI 混淆、JWT 签名绕过等经典 OAuth 实现漏洞。
- 已经发送给客户端并保存的明文如何回收。
- 资源提供商、数据库、浏览器或操作系统被完整攻陷。
- 流量分析、侧信道攻击和拒绝服务。
- 多租户生产环境下的密钥托管和隔离。

## 八、当前原型的限制

当前实现会在 TLS 连接内直接返回派生字段密钥，因此还没有做到：

- 使用客户端公钥封装密钥。
- 强制 capability 过期时间。
- 使用 jti 防重放。
- 密钥轮换。
- 单任务撤销。
- 不可篡改审计日志。

这些限制不能在未来报告中描述为已经解决。

## 九、重要适用范围

资源服务器在加密字段之前能够看到完整明文。因此当前方案主要防止第三方应用读取任务外字段，并不保护用户免受恶意资源提供商的影响。这个假设必须在最终报告和答辩中明确说明。
